# Firebase configuration

Use Firebase Authentication for parent accounts and Firebase Storage for child-explicitly-shared photos. Structured records and image metadata belong in MongoDB; image bytes are never persisted in MongoDB. Voice recordings stay local.
Create parent/child Firebase Android app registrations. Download google-services.json privately into each android/app (ignored); the optional Google Services Gradle plugin applies only when that file exists. Supply Dart Firebase options as documented. FCM background initialization requires native Firebase configuration. Enable email/password auth and verification.
Storage rules deny all direct client access. The authenticated Node API uses least-privilege Admin credentials to normalize images, strip metadata, store JPEGs, and authorize family-scoped downloads. Never publish bucket objects or create permanent download tokens. Configure FIREBASE_STORAGE_BUCKET and Application Default Credentials securely. Deploy firebase/storage.rules using your Firebase project tooling. Bucket creation/billing requirements must be checked with current provider terms; no zero-cost promise is made.
Images expire after 24h in API reads; a durable cleanup worker deletes objects, retrying failed deletions. Mongo family deletion creates cleanup jobs without retaining membership or image payloads. Monitor cleanup failures. Do not delete Mongo image metadata via TTL before object cleanup. Enable Firebase-side lifecycle retention as defense in depth when supported. Real Storage integration is untested without a configured project.
